plain definition, so conversations and code stay consistent and concise.

Idea from https://github.com/mattpocock/skills.

## Glossary

**benchmark** — Systematic comparison of four taxonomic-assignment methods (dada2, sintax, lca, blastn) across **nine reference databases** (`db_list` in `config.R`, from `benchmark_dbs`: 3 sources x 3 simplifications) for the taxonomic assignment of Fungi (ITS metabarcoding), on three inputs (ASV, OTU, ITSx ASV). Performance is evaluated on two mock communities (Pauvert, Tedersoo), cross-validation, in silico simulations, and biological datasets (Bokulich 2020 four-dataset approach). The **method set is a deliberate zoom, not a gap**: Orsholm et al. 2026 settled the algorithm-family question for fungal ITS, so the complexity goes to the database and voting layers (see *method zoom*).

**assignment method** — Algorithm used to assign a taxonomic label to an ASV/OTU sequence. The four methods in scope: `dada2` (RDP naive Bayes classifier, `assignTaxonomy`), `sintax` (vsearch SINTAX bootstrap), `lca` (Lowest Common Ancestor), `blastn` (BLAST nucleotide search with a vote algorithm).

**reference database** — FASTA file providing labelled sequences against which query ASVs are classified. Built by `make_databases.R` from a *reference source*, in dada2 and sintax header formats, as a full, `_Fungi` (kingdom exactly Fungi), `_Fungi_rep` (see *fungi + rep*) or `_Fungi_cut` variant (then trimmed with cutadapt at ITS1F and at the reverse complement of ITS2 when found; records without primer sites are kept whole, decision 23). The benchmarked set is `config.R::benchmark_dbs`. Procedure: `docs/reference_databases.md`.

**reference source** — A general FASTA release downloaded as-is (`dbpq::download_unite_db()` / `dbpq::download_eukaryome_db()`) into `data/data_raw/refseq/sources/<source>.fasta`, listed in `config.R::reference_sources` with its URL and DOI. Source names carry the release (`Unite_s_all_20250219` = UNITE 19.02.2025 eukaryotes with singletons, `Unite_all_20250219` = without singletons, `EUK_ITS_v2.1`), so a new release yields new file and target names. Provenance in `sources/manifest.csv`.

**general FASTA** — The provider's reference release with taxonomy in `k__`/`p__` form (UNITE: `Name|Acc|SH|type|k__…`; EUKARYOME: `ID;k__…`), before conversion by `derive_dada2()` / `derive_sintax()`.

**EUKARYOME name qualifiers** — Annotations EUKARYOME adds to rank values: the kingdom or order of a homonym (`g__Lactarius(Fungi)`), bracketed genera (`g__(Candida)`), `.s.str` (sensu stricto), `.nom.prov` (provisional name). `make_databases.R::general_headers_fixed()` keeps the name only before conversion, so names match the mock and sintax bootstraps parse; placeholders (`Xxx.gen05`, `.fam.incertae.sedis`) are kept.

**`values_map`** — Tibble built by `build_values_map()` (`R/values_map.R`) from `db_list`, enumerating all (method, parameter, db, input) combinations to benchmark: **21 method/parameter rows** (dada2 and sintax `min_bootstrap`, lca `lca_cutoff`, blastn 3 votes x `min_id`) x (9 databases with the raw ASVs + 9 with the OTUs + the 6 databases of `config.R::itsx_db_list` with the ITSx input; `preprocess` = `none`, `otu` or `itsx`), i.e. **504 rows** since 2026-09-17 (item 0.4a). `input_pq` names the phyloseq target an assignment reads; ITSx rows have `itsx_`-prefixed `full_name`s. `compute_name` groups the rows computed together: one computation per method x database x input (`compute_<method>__<db>`, `otu_compute_…`, `itsx_compute_…`, **96 in total**) serves several rows, whose thresholds, votes or copies are derived afterwards (`R/assign_compute.R`, ROADMAP S8.2). Each row carries `full_name` (the targets name, pinned by `tests/test_values_map.R`), `db_path` (format chosen by method, `mini_*` when `mini_db`), `ref_file` (name of the file target tracking `db_path`: `ref_sintax__<db>` / `ref_dada2__<db>`), and the crew `controller`. `pipelines/assign_taxo.R` dispatches one target per row; `d_all_taxo` is assembled by `tarchetypes::tar_combine`. `build_cv_values_map()` is the cross-validation counterpart.

**`_targets.yaml` / `TAR_PROJECT`** — Seven named targets projects: `dada2`, `assign_taxo`, `cross_val` (production stores), `assign_taxo_mini`, `cross_val_mini` (same scripts on the `mini_*` databases, own gitignored stores) and the dataset pair `dada2_tedersoo_illumina` / `assign_taxo_tedersoo_illumina`. `Sys.setenv(TAR_PROJECT = "assign_taxo"); tar_make()`. `run_project()` (`R/run_project.R`) wraps `tar_make()` + `tar_prune()`; sourcing `make.R` runs every step, so source `R/run_project.R` to build a single project.

**`load_pqverse()`** — `R/load_pqverse.R`; loads the sister packages from their development checkouts under `PQVERSE_PKG_DIR` (decision 10). Called by every pipeline, inside every crew-worker target, and by `analysis/00_setup.R`. `pqverse_versions()` records version + git commit in the `session_info` target of each store.

**analysis chapters** — Quarto project in `analysis/`: `00_setup.R` (shared setup and helpers), `01_load_and_clean` (writes `analysis/_cache/*.rds`), `02_q1_methods`, `03_q2_databases`, `04_q3_consensus`, `05_m2_costs`, `06_cross_validation`, `in_silico_simulation.qmd`, `sandbox/`. Each chapter starts with `here::i_am()` because `_quarto.yml` is a `here` root criterion.

**tidypq** — pqverse package of tidyverse-style verbs for phyloseq objects (samples, taxa, occurrences, tree scales). Adopted in this project (decision 13): `tax_table_to_df()` to read a tax_table as a tibble, `mutate_taxa_pq()` to write columns back, `pq_to_tidy()` instead of `psmelt()` (unassigned ranks become `"Unknown"`, zero abundances are dropped). Phyloseq slots (`@tax_table`, `@otu_table`) are no longer edited by hand where a verb exists.

**ITSx input (`d_asv_itsx`)** — Copy of `d_asv` whose sequences are the ITS1 extracted by ITSx (`R/itsx.R`, `itsxenv` conda env), without the 18S flank and the 5.8S start of the ITS1F–ITS2 ASVs; ASVs ITSx does not detect keep their full sequence. ITSx only trims the flanks here: all organism profiles are used and its ability to keep Fungi only is deliberately not used. It receives the same negative controls as `d_asv` and feeds the `itsx_<method>` assignments (question Q4, decision 19).

**mock community** — Lab-made community of known fungal taxa, the primary ground truth. Two of them: **Pauvert et al. 2019** (189 strains, 181 species, ITS1, the `store_dada2` dataset) and **Tedersoo et al. 2026** (103 species, full ITS, `store_dada2_tedersoo_illumina`). Each is scored against its *per-unit truth* built from the Sanger sequences of its Table S1 (`data/data_raw/metadata/`), not against the former set of expected taxa (`taxo_mock.csv`).

**fake taxa** — Negative-control sequences injected before assignment: shuffled ASV sequences (`add_shuffle_seq_pq`, prefix `fake_`) and sequences from an external FASTA (`add_external_seq_pq`, prefix `external_`): `fake_ref_asv_100.fasta`, 100 non-Fungi records of `config.R::fake_ref_source` drawn by `derive_fake_ref()`, tracked by the file target `fake_ref_file` so a regenerated file invalidates every assignment. Taxa matching `^fake_|^external_` are the TN denominator in `tc_metrics_mock()`.

**`tc_metrics_unit()` / `tc_metrics_unit_vec()`** — The scoring this project uses since 2026-09-22 (comparpq, item 0.7): one confusion-matrix cell **per unit and per rank** against the *per-unit truth*, as in Hleap et al. 2021. Returns the four cells plus FDR, PPV, TPR, TNR = TN / (TN + FP), F1, ACC, MCC (0 on a zero margin) and the *control metrics*. `truth_depth` decides where a unit leaves the matrix; `external_scoring` places the `external_` controls. Called through `R/score_assignments.R::score_assignments()`, one call per scoring group.

**`tc_metrics_mock()`** — The older comparpq function: set-membership metrics for each (method x db x rank) against a list of expected taxa. **Superseded here** by `tc_metrics_unit()` and kept in comparpq for a mock that comes with no per-sequence truth.

**consensus voting / `resolve_taxo_conflict()`** — `comparpq` function that combines taxonomy assignments from multiple methods/databases into a single consensus call. Five strategies: `unanimity`, `consensus`, `abs_majority`, `rel_majority`, `preference`. Controlled by `strict` (boolean) and `nb_agree_threshold` (integer: 1, 2, or 3).

**cross-validation (CV)** — k-fold held-out evaluation of each (method, db) pair using the reference database itself as the source of truth. Implemented in `R/cross_val.R` (`cross_val()` and `cross_val_param()`), run via `pipelines/cross_val.R` → `store_cross_val`. Key parameters in `config.R`: `cv_fold_number`, `cv_fold_tested`, `cv_max_seq` (**3 folds** and 5000 queries in production since the B24 fix, 2 folds and 200 when `mini_db`), `cv_oversample`, `cv_reduce_reference` (FALSE: the reference is the whole database minus the tested queries) and `cv_n_workers_fast` (2, because a dada2 CV target on a full reference needs 23-45 GB).

**CV reference pool** *(historical, fixed 2026-09-16)* — Until the B24 fix, the reference a cross-validation target actually searched was the records drawn by `cross_val()` (`cv_oversample x cv_max_seq`), *not* the whole database. `cv_reduce_reference = FALSE` now keeps the whole database minus the tested queries (Bokulich design). The paragraph below describes the results stored before that fix. With the production settings this is 5 413 records on `Unite_all_20250219` (3.45 % of it), 6 284 on `EUK_ITS_v2.1` (0.33 %) and 5 295 on `EUK_ITS_v2.1_Fungi` (0.49 %): the pool grows until 5 000 of its records carry the ITS2 site, so its size follows that site rate and never the database size. The tested fold is removed from it in the standard variant. This is the documented behaviour of `max_seq`, and it drives the D1a results: blastn abstains when no hit passes its filters (87–95 % NA at Genus), lca and sintax answer with the nearest available taxon and are wrong instead. The CV database axis therefore compares taxonomic composition at equal reference size, not the databases as the mock community uses them (ROADMAP B24, found 2026-09-16).

**trimmed CV queries** — In cross-validation, the test sequences are cut to the ITS1F–ITS2 amplicon with cutadapt, like the reads of an Illumina run (`R/cv_queries.R`, decision 24); the training part keeps full-length records. Records without the ITS2 site are never queried but stay in the training part; `cv_oversample` records are drawn per wanted query so that each database gets `cv_max_seq` queries. The queries of a `_Fungi_cut` database, whose records no longer hold the primer sites, are drawn and trimmed from its `_Fungi` source (`query_fasta`) and paired by name with the `_cut` records. Records are named by their sintax-format identifiers for every method, also for dada2, whose headers are the taxonomy only (`id_fasta`, ROADMAP B22).

**OTU taxonomy (`d_otu_taxo`, `unit = "OTU_derived"`)** — Q5 object built in chapter 01, kept beside the **directly assigned** OTUs (`d_all_taxo_otu`, `unit = "OTU"`, decision 28) so that Q5 compares "assign then cluster" with "cluster then assign": `d_all_taxo` merged into the 97 % vsearch clusters of the ASVs (`otu_clusters` target, `otu_membership()`), each assignment column keeping the value all member ASVs assigned at that rank agree on (`resolve_otu_taxonomy()`, `unanimity`, NA ignored). No assignment is rerun on OTUs; the negative controls are not clustered (decision 25). Its metrics are rows of `res_comp_tax` with `unit == "OTU_derived"`.

**`remove_tested`** — Cross-validation parameter (`remove_tested_sequences = TRUE/FALSE`) that controls whether the sequences being classified are excluded from the reference database (TRUE = standard, non-leaked; FALSE = leaked, upper-bound estimate).

**in silico simulation** — D1b: InSilicoSeq generates simulated fastqs from records of `Unite_s_all_20250219` (sequencing errors included), which gives a per-sequence ground truth. The miaSim branch (community matrices from neutral / niche models) was dropped on 2026-09-17 (scope: no community ecology) and removed from `analysis/in_silico_simulation.qmd` on 2026-09-22 (ROADMAP 0.9); its code is in the git history.

**`store_dada2` / `store_assign_taxo` / `store_cross_val`** — Three independent `{targets}` stores at the project root, one per production project of `_targets.yaml`; `make.R` runs all three in order. `store_assign_taxo` depends on `store_dada2/objects/d_asv` as a file target. The notebooks read them via `tar_read(..., store = here("store_assign_taxo"))`. `meta/meta` is tracked in git (decision 9), `objects/` is not.

**`autometric` / `with_autometric()`** — Per-target logging of wall time, peak RAM and mean CPU. Because `autometric::log_start()` only logs its own process, `with_autometric()` (`R/autometric_helpers.R`) starts the logger *inside* the crew worker and writes one file per target and per run under `data/data_final/autometric/<pipeline>/`. `summarise_autometric_costs()` keeps the newest file per phase; `benchmark_costs` (assignments) and `benchmark_costs_dada2` (denoising) are the aggregated targets.

**`config.R`** — Single shared-constants file sourced by the three pipelines, `make_databases.R` and `analysis/00_setup.R`. Contains primers (`fw_primer_sequences`, `rev_primer_sequences`), `n_threads`, `seq_len_min`, `prop_fake`, paths, conda prelude for cutadapt, the primer-trimming settings (`primer_min_overlap`, `cut_discard_untrimmed`), `n_workers`, `targets_seed`, the CV knobs, `db_list`, `db_meta`, and `mini_db` (derived from `TAR_PROJECT`).

**`combine_taxo_assignments()`** — Helper in `R/combine_taxo_assignments.R` used by `tarchetypes::tar_combine` to merge per-(method, db) `tax_table` columns into one wide phyloseq object. Detects new columns via `setdiff(colnames(new_tt), colnames(base_tt))`; does not need to know per-row suffixes.

**`proposals_for_dbpq.md`** — Inventory of the helpers still implemented locally in `make_databases.R` / `R/create_fake_pq_from_refseq.R` that fit `dbpq`'s scope, plus the dbpq defects worked around here (§0). **Four live proposals** (§1, §2, §4, §6) since 2026-09-22; §3 and §5 are **withdrawn** because their call sites were dead code, under the rule **do not upstream dead code** — a proposal is live only while its local call site is reachable from `derive_all_variants()`. Numbering is kept stable, a withdrawn item keeps its number. Consult it before adding a new helper.

**`docs/experimental_design.md`** — Design document (2026-09-16) recording, objective by objective, what is tested, against which truth, and at what *measured* cost. Holds the **objective → grid map** (only Q2, Q4 and D1a cost anything; Q1, Q3, Q5, M1 and M2 re-read material already computed, so splitting the objectives into separate projects would cost more, not less), the dataset table with each one's **ITS region** (the constraint that decides which databases a dataset may be assigned against), the measured cost of a production run, and the open implications. Read it before planning a run or adding a dataset.

**`docs/objectives_design.md`** — Design document (2026-09-17) listing, objective by objective, the input data, the additions (negative controls), the databases, methods, parameters and, above all, the metrics that answer each question, as defined in the code (`comparpq::tc_metrics_mock_vec()` read line by line). Section 4 holds the developer's decisions of 2026-09-17, verbatim; section 5 what is still open.

**`docs/hleap_2021_metrics.md`** — Hleap et al. 2021 metrics read from the paper and from their code (`TA_pipes`, `optimize_n_score.py::score()`), compared line by line with `comparpq::tc_metrics_mock_vec()`: per-sequence truth, one confusion cell per sequence per rank, shuffled sequences assigned count as FP, no TNR, parameters tuned on one third of the mock and scored on the other two thirds.

**M1 metric set** — Primary performance metrics used in results figures: F1 + MCC (Hleap 2021) + TAR/TDR per taxonomic rank. TP/FP/FN/TN go to supplementary material only. Decided 2026-05-19.

**M2 environmental metrics** — Carbon-footprint and compute-cost layer: `wall_time_s`, `peak_resident_mb`, `mean_cpu_pct` from `benchmark_costs`, converted to CO₂eq via `greenAlgoR`.

**`cutadaptenv`** — Conda environment name containing `cutadapt`. Required by the DADA2 pipeline's primer-removal step, the `_Fungi_cut` database derivation and the trimming of the CV queries; the scripts prepend `source ~/miniforge3/etc/profile.d/conda.sh && conda activate cutadaptenv &&` before each cutadapt call.

**`unit` (column of `res_comp_tax`)** — Which input a metric row was scored on: `ASV` (`d_all_taxo`, the raw and ITSx columns plus the consensus columns), `OTU` (`d_all_taxo_otu`, the 97 % OTUs assigned directly) or `OTU_derived` (the same clusters, taxonomy resolved from the member ASVs). `OTU` against `OTU_derived` is Q5's "cluster then assign" versus "assign then cluster".

**`external_scoring`** — Whether the `external_` controls enter the confusion matrix (`"matrix"`) or stay aside (`"aside"`). They enter it only when the reference database cannot hold them: `"matrix"` on the `_Fungi` databases, `"aside"` on the whole releases and on the `_Fungi_rep` (where `ext_correct` is read at the kingdom only). A consensus column has no database and is scored both ways, so `res_comp_tax` holds two rows for it.

**`default_view()`** (`analysis/00_setup.R`) — The view of `res_comp_tax` that chapters 02 to 05 read: one dataset, one input (`ASV`) and one reading of the consensus columns. Without it a chapter averages the three inputs and counts every consensus column twice.

**Placeholder epithet** — A species name that identifies nothing below the genus (`Phoma sp`, `Alternaria sp.`, `Fusarium spp`). `R/mock_truth.R::species_name()` gives such a strain no species truth, so the unit stops at Genus: the chapter turns every `<Genus>_sp` assignment into NA too, and a truth nobody can match would score FN or FP whatever the method answered.

**method zoom** — The decision (2026-09-22, decision 37) to keep the method axis at four representatives instead of re-running a classifier shoot-out: Orsholm et al. 2026 showed that for fungal ITS composition-based classifiers beat phylogenetic placement and generic similarity search, so the algorithm-family question is taken as settled and the complexity goes to the database and voting layers. Honest reading of the four: **2 composition-based** (dada2's RDP naive Bayes, sintax's k-mer bootstrap) x **2 similarity-search** (lca, blastn), with blastn as the *abstaining* contrast — `lca` is search-based, not composition-based, and the manuscript must not imply otherwise.

**abstaining method** — A method that returns NA rather than the nearest name when nothing passes its threshold (blastn, through `min_id` and `min_cover`). Its sweeps trade FP for NA; `lca` does the opposite (it answers with the nearest available taxon and errs instead). The contrast is what the Q1 parameter sweeps measure.

**effective voters / redundant voter** — The number of *independent* classifications a consensus really aggregates, which is smaller than its column count: `Unite_all_20250219` is a subset of `Unite_s_all_20250219`, and `lca` and `blastn` read the same reference through the same vsearch/BLAST hits. A vote over correlated columns beats any single column by construction, so a Q3 gain is only a voting result once reported against the effective number of voters (ROADMAP C22-P6, C22-P21; decision 39).

**closed-book benchmark** — A benchmark whose every truth taxon is present in the reference, which is what a mock community is by construction (134-163 of the 181 Pauvert species are found by exact name match in UNITE / EUKARYOME). It measures *identification of known taxa*, not discovery of novel lineages — the case practitioners actually struggle with, and the question Orsholm et al. 2026 made central. The proposed opening move is the **one-species-out** test (ROADMAP C22-P7): remove every record of one mock species from a reference and score its ASVs.

**held-out confirmation** — Proposed rule (ROADMAP C22-P3) for any *recommendation*: select the best (method x database x parameter) on the Pauvert mock and confirm it on Tedersoo, so a parameter set is never recommended from the mock that picked it. The parameter sweeps themselves stay untuned and reported in full (decision 31); only the recommendation is held out.

**real units vs controls (denominators)** — Proposed reporting rule (ROADMAP C22-P8): headline F1 / PPV / TPR computed on the **real units only**, with the negative controls carried by their own rates (`NA_fake`, `ext_fungi`, `ext_correct`, `ctrl_assigned`). Mixing them makes the absolute metrics depend on `prop_fake = 0.5` and on the number of `external_` records, which are constants of the harness rather than properties of the methods.

**declaration of interests** — The paper must state that the harness and part of the benchmarked software share an author (MiscMetabar's assigners, comparpq's voting and scoring), that the package commits are pinned per run by the `session_info` targets, and that the engines (vsearch, BLAST+, dada2) are independent third-party tools, so the wrapper can only flatter its own parameter plumbing — which `tests/test_assign_compute.R` audits against the direct calls (decision 40, ROADMAP C22-N1).

**`critique_2026-09-22.md`** — External review of the project's **aims** (are they well defined, are they interesting: C1-C5, threats T1-T9, propositions P1-P13) and of its **code size and distribution** (S1-S7, R1-R6, P14-P20). Its **addendum** records the developer's framing answer of the same day, which withdraws part of the review (Q3 stays primary) and makes P6 required. Its proposals are ROADMAP items `C22-…`; none is applied.

**`literature_2026-09-22.md`** — Positioning against the six benchmarks this project must cite (Hleap 2021, Orsholm 2026, Winand 2025, Graetz 2025, Bayer 2025, Pauvert 2019), a comparison matrix of their axes, and the six claims no published benchmark makes together. Written from abstracts and records: verify wording before quoting in the manuscript.

**`ROADMAP.md` / `HISTORY.md`** — Since 2026-09-22 (decision 41, ROADMAP C22-P19) the todo and the archive are two files: `ROADMAP.md` holds one line per open item, `HISTORY.md` every ticked item, dated narrative and past decision (sections 3 to 3d). A new decision is written in `docs/objectives_design.md` §4 and summarised in `HISTORY.md` §3d, never stated for the first time in `ROADMAP.md`.

**`AGENTS.md`** — The agent-facing guide (former `CLAUDE.md`, renamed 2026-09-22): what the project is, the design, the layout, how to run the pipelines and render the analysis, the pipeline architecture and the external dependencies. `CLAUDE.md` is a two-line pointer to it.

## Key decisions

**Four assignment methods, IdTaxa excluded (2026-05-19)** — The methods set is fixed at dada2, sintax, lca, blastn. IdTaxa is excluded because it requires a separate training step, making cost comparisons unfair. The `idtaxa` block remains commented out in `values_map`; the manuscript will include a one-line justification pointing to Murali et al. 2018.

**No SSU database (2026-09-15, revises 2026-05-19)** — The 2026-05-19 decision kept only `EUK_SSU_v2_Fungi_cut`, on the belief that ITS lies inside the 18S gene. It does not: trimming an SSU record at ITS1F leaves the 46 bp of 18S that start the ASVs, so the SSU release is no longer benchmarked (ROADMAP decision 7, S6.9).

**Mini databases are smoke-test only (2026-05-19)** — `derive_mini()` in `make_databases.R` produces fast 10 000-line database subsets for iteration. They are excluded from all Results figures; use `dplyr::filter(!startsWith(db, "mini_"))` before any publication figure.

**Parallel pipeline over sequential** — `pipelines/assign_taxo.R` replaces the archived `Archives/script_assign_taxo.R`. Each (method, db) reads `d_asv_for_assignation` directly and runs in parallel via `crew_controller_local`; the sequential predecessor had each target depend on `previous_target`, creating a bottleneck.

**Biological validation dataset: Taudière et al. 2018 (2026-05-19)** — Tree endophyte ITS data from Taudière et al. (doi:10.1016/j.funeco.2018.07.008), with `site` and `height` as sample modalities. No objective ground truth exists; metrics are agreement-only (Jaccard, Bray-Curtis, richness). Pending: fastq availability check and SRA/Dryad/ENA fetch.

**Structural decisions (2026-09-10)** — Figures are not versioned (`figures/` gitignored); `store_*/meta/meta` stay tracked; the reference code is the dev checkout of every pqverse package (`load_pqverse()`); SRR30413326 joins as a second mock (D1d); tidypq is adopted in the notebook and the pipelines (ROADMAP S5.x); smoke tests run in the `*_mini` targets projects, never in a production store. Details in ROADMAP section 3b.

**blastn query cover 80 % (2026-09-11)** — `config.R::blastn_min_cover`. BLAST `qcovs` is the share of the ASV covered by the alignment with a reference, whatever the reference length. The ITS1F–ITS2 ASVs start with 30–45 bp of 18S that ITS references lack, so the `assign_blastn()` default of 95 rejected most true hits (ROADMAP decision 18, critique 07 B18). ITS extraction with ITSx is the proposed alternative (Q4).

**Benchmark grid per dataset (2026-09-16, counts superseded 2026-09-17)** — Every new dataset gets the **full grid** — **96 computations** since the nine-database design, not the 44 written below — and **ITSx runs on every dataset**, for maximum comparability with the mock. Cost is therefore linear in the number of datasets, which is the only remaining lever: the objectives share their computations, so splitting them would cost more, not less (`docs/experimental_design.md`). Three consequences: `itsx_region` **became per-dataset** on 2026-09-17 (item 0.5, `bio_datasets$itsx_region`); the ITS2 datasets (GSSP, Korhonen) would need `_ITS2_cut` reference variants, which the *zoom* strategy defers; and the biological communities serve only to compare **NA counts** against real data, so abundances are not needed.

**No `_cut` arm for the Tedersoo mocks (2026-09-16)** — Their primer pair (ITS9mun / ITS4ngsUni) has essentially no site in an ITS reference: 5' present in 2.2 % of `EUK_ITS_v2.1_Fungi` records, 3' in 0.004 %, against 68 % for the 3' site of ITS2 that makes `_Fungi_cut` a real trim. Trimming therefore left **96.9 % of the records unchanged** and produced a 1.4 GB duplicate of `_Fungi`. This is a **Q2 result, not a bug**: for a full-ITS amplicon an ITS reference is already at the right region, so there is nothing to trim. **Fixed on 2026-09-17** (item 0.1b): the substitution is gone from `config.R` and `bio_datasets$cut_suffix` is `NA`, so Tedersoo runs on the same nine databases as Pauvert.

**Framing of the manuscript (2026-09-22)** — Answering `critique_2026-09-22.md`, the developer settled what the paper claims (decisions 37-40, `HISTORY.md` §3d; `literature_2026-09-22.md` §4): Orsholm et al. 2026 is the **foundation, not a competitor**, so the four methods are a deliberate *method zoom*; the two complexity layers are **database composition (Q2) and voting across classifications (Q3)**, which makes Q3 a primary axis and the *effective voters* check mandatory; the whole grid runs in **one language and one dependency stack** (pqverse), whose flip side is the *declaration of interests*. Left open: the **primary endpoint** (decision 42, ROADMAP C22-P2).

**Decisions of 2026-09-22** — Two rules settled while implementing the grid. (i) **A representative of a `fungi + rep` database must stay below 97 % identity with every `external_` control** (`config.R::rep_max_identity_to_external`): the rule applies to the representatives only, since the whole releases contain the controls by construction (they are records of `fake_ref_source`, which is what makes `ext_correct` computable there) and the `_Fungi` databases contain none. (ii) **The Q3 consensus votes over the default settings only**, one column per method and database (4 x 9 = 36, equal weight): with the full sweep blastn would bring 12 columns per database out of 21 and carry 57 % of the vote.

**Scope and grid decisions (2026-09-17)** — The benchmark tests **taxonomic assignment of Fungi and nothing else**: miaSim / Hubbell simulations are dropped, and biological datasets are read only through `NA_real`, `NA_fake` and `ext_fungi` across studies. Database grid `[EUK_ITS_v2.1 | Unite_all | Unite_s_all] x [all | Fungi | Fungi + rep]`, with **no cutadapt-trimmed database in the main grid** (96 computations per dataset). Strategy: answer secondary questions with **targeted zooms** rather than multiplying the total computation; trimming (`Fungi + rep cut`) is tested at the end only on the few best database x method combinations, on the Pauvert mock, and cross-validation may run on fewer databases. `Fungi + rep` adds 5 % of the fungal record count as non-fungal records drawn from the same source's `all` release, spread equally (water-filling) over the kingdoms with at least 10 records (UNITE releases) or 100 records (EUKARYOME), placeholder labels such as `cf.*`, `*.reg*`, `_mitochondrion` excluded, without the 100 `external_` controls; the `external_` controls must themselves come from retained kingdoms, so `fake_ref_asv_100.fasta` was regenerated on 2026-09-17 from the 13 kingdoms retained in all three releases (`external_control_kingdoms()`). OTUs (`d_vs`, no MUMU, no ITSx) are assigned directly. `external_` controls count in TN on Fungi databases only; `ext_correct` is scored at every rank on `all` databases and at Kingdom on `Fungi + rep`. lca gets an `lca_cutoff` sweep {0.8, 0.9, 1} derived in MiscMetabar from one stored hit table, blastn a `min_id` sweep {90, 92, 95, 97}. Cross-validation queries fungal records only. New metrics `NA_real`, `NA_fake`, `ext_fungi`, `ext_correct`, `ctrl_assigned`, `misassign_seq`; scoring decided after Hleap et al. 2021 (see *per-unit truth* and *Hleap scoring*). Only the `external_` control reference is implemented; details and kingdom lists in `docs/objectives_design.md` sections 1.3 and 4, implementation plan in ROADMAP section 0.

**per-unit truth** — The taxon a mock unit (ASV or OTU) really belongs to, from the Sanger sequence of each strain (Pauvert and Tedersoo Table S1, `data/data_raw/metadata/`): identity ≥ 99.5 % and the shorter of the two sequences covered at ≥ 99.5 %; ties between strains stop at their lowest common rank; units without a match stay in the scoring. Names: the submitted name is the truth, the GBIF accepted name also counts as correct at Species and Genus, ranks above Genus come from the GBIF lineage (`taxinfo::gna_verifier_pq(classification_col = TRUE)`). Decided 2026-09-17, **implemented 2026-09-22** in `R/mock_truth.R` (`build_mock_truth()`, `config.R::mock_sanger_tables`): 149 / 196 Pauvert ASVs and 99 / 238 Tedersoo ASVs carry a truth. `docs/hleap_2021_metrics.md` §6.

**Hleap scoring** — Each scored unit falls in one cell per rank, as in `TA_pipes::optimize_n_score.py::score()`: real unit given its own truth → TP, another name → FP, NA → FN; `fake_` named → FP, NA → TN; `external_` enter the matrix on Fungi databases only. TNR = TN / (TN + FP). Replaces the set-membership metrics of `comparpq::tc_metrics_mock_vec()`; decided 2026-09-17, **implemented 2026-09-22** as `tc_metrics_unit()`.

**control metrics** — `NA_real` (share of real units left NA), `NA_fake` (share of `fake_` left NA), `ext_fungi` (share of `external_` assigned Kingdom Fungi, always an error), `ext_correct` (share of `external_` given their true non-fungal lineage), `ctrl_assigned` (controls given a value), `misassign_seq` (real units given a wrong taxon). Rates, so they compare across databases and units where ACC and MCC do not.

**zoom** — Project strategy (2026-09-17): a secondary question (trimmed references, cross-validation breadth) is answered on the few best combinations of the main grid rather than by adding a grid level; e.g. `fungi + rep cut` on one UNITE and one EUKARYOME database, Pauvert mock only.

**`tar_option_set(seed = 22)`** — Fixed random seed set in both `pipelines/dada2.R` and `pipelines/assign_taxo.R`. Must be preserved when modifying targets so pipeline re-runs stay reproducible.
